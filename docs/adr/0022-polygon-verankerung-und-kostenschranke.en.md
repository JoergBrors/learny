## Decision

1. **Networks:** Development/test uses Polygon **Amoy** (chain ID 80002, test POL, no real fees); production uses Polygon PoS **mainnet** (137). RPC URLs are configurable (`BLOCKCHAIN_RPC_URL_AMOY/MAINNET`), never hardcoded. Each credential records network and chain ID at issuance; changing networks does not modify existing credentials or anchor them on the new network.
2. **Operating modes:** `BLOCKCHAIN_ENABLED=false` (signed badges only), testnet (default `BLOCKCHAIN_NETWORK=polygon-amoy`, `BLOCKCHAIN_AUTO_ANCHOR=true`), and mainnet. **Mainnet requires all of:** `BLOCKCHAIN_NETWORK=polygon-mainnet`, `BLOCKCHAIN_MAINNET_ENABLED=true`, **and** explicit administrative approval (`POST /api/admin/blockchain/mainnet-approval` with confirmation text). Approval applies only to the currently configured wallet, can be revoked, and is audited. The ASP.NET environment never switches to mainnet automatically. `BLOCKCHAIN_SIMULATE=true` simulates locally (network “simulation,” clearly identified as simulated everywhere, never mistaken for mainnet).
3. **Anchors without smart contracts:** Send a zero-value transaction from the wallet to itself, with data `LCv1` + a 32-byte Merkle root. No personal data, NFTs, tokens, or contract execution costs. Verification reads the transaction via RPC and checks sender, expected anchor data, receipt status, confirmations, and chain ID.
4. **Merkle batching:** Leaf = SHA-256(0x00 ‖ badge hash); node = SHA-256(0x01 ‖ left ‖ right); an unmatched odd node is carried forward unchanged. Ordering follows issuance time/ID. Each credential gets its own proof path (`certificates.merkle_proof_json`), and each batch has a unique root (unique index per network: the same set produces the same batch, never anchored twice). A batch becomes due at `BLOCKCHAIN_BATCH_MAX_SIZE` (100) credentials or `BLOCKCHAIN_BATCH_MAX_WAIT_MINUTES` (60); administrators may only reduce these thresholds.
5. **Hard cost ceiling** (`AnchorCostGuard`): Estimated cost = gas limit (estimate + 20%) × (gas price × 1.5) × (POL/EUR rate × 1.25). Maximum cost per credential = min(admin/environment limit, **EUR 0.001**) — batch cost divided by credential count. **Do not submit** if gas/gas price is unknown, the price quote is missing or stale (older than 15 minutes), the limit is exceeded, or the batch is empty. Perform the check **twice using fresh data** (before signing and immediately before signing). The transaction uses the tighter bound for `maxFeePerGas` and the gas limit. Retries recalculate the bound and never escalate or bypass a failure. There is no fallback submission route. Also refuse to send without mainnet approval, signer, correct chain ID, or sufficient wallet balance. Blocked credentials remain “pending/cost ceiling exceeded”; their badges are unaffected.
6. **Idempotency and retries:** Persist the signed raw transaction **before** broadcasting it. Retries rebroadcast the identical transaction (same hash). After 90 minutes without inclusion, mark the batch failed; an administrator can reschedule it subject to full cost checks. Parallel processing is serialized. Consider a credential “blockchain confirmed” only after `BLOCKCHAIN_CONFIRMATIONS` (30) confirmations **and** successful anchor verification.
7. **Per-batch cost tracking:** Gas, effective gas price, fee in wei, exchange rate and timestamp, estimated/actual EUR costs, per-credential cost, and estimated savings from batching (only with reliable data). Testnet/simulation reports actual expenses as **EUR 0**; hypothetical mainnet costs appear separately as “simulated.”
8. **Signing — open decision:** EVM transactions require Keccak-256 (not SHA3-256) and secp256k1 signatures; these are not both available through base .NET (secp256k1 is unavailable under Windows). Custom cryptography is excluded. The application therefore defines `IAnchorSigner` with a default “not configured” implementation; the private key must not enter this application until a solution is chosen. The pseudo-signer is only for simulation/tests (local RPC required). **Options requiring a decision:** (a) permit a NuGet package such as Nethereum through a new ADR (easiest, key managed as a secret); (b) Azure Key Vault / Managed HSM using an EC `SECP256K1` key to sign transaction hashes, with Keccak-256 and RLP implemented locally using known test vectors—the key stays in the vault; or (c) external signing service. Use separate technical wallets for testnet/mainnet. Configure the address in `BLOCKCHAIN_WALLET_ADDRESS`; monitor its balance and refuse submission when funds are insufficient.
9. **Price source:** Configurable HTTPS endpoint (`BLOCKCHAIN_PRICE_URL`, JSON path), with no hardcoded rate. On retrieval failure use the last known quote along with its age; stale quotes block submission.

## Practical Feasibility of the EUR 0.001 Limit (Estimate, Not Measured)

An anchor containing 36 bytes of data needs approximately 21,576 gas. At 30 Gwei, that is about 0.00065 POL. At EUR 0.20/POL, roughly EUR 0.00013, or about EUR 0.00024 after safety factors (1.5 × 1.25)—**below** EUR 0.001 even without batching. Very high gas prices (Polygon mainnet minimum priority fee: 25 Gwei) or a high POL/EUR rate may hit the ceiling. Batching spreads the fixed cost (100 credentials → one hundredth of the cost each). Actual Amoy measurements are unavailable because sending is not enabled. The ceiling only protects the EUR estimate as long as exchange-rate changes between quoting and settlement stay within the 25% buffer; an unconditional EUR guarantee is impossible with changing rates. RPC/infrastructure expenses are separate.

## Operating without Blockchain / Failures

When `BLOCKCHAIN_ENABLED=false`, RPC is unavailable, funds are insufficient, or the price feed is missing, badges remain signed and verifiable. Anchoring stays pending (“anchoring pending” or “cost ceiling exceeded”) and may be processed later. Nothing is lost.
